# Screenshot Evidence Guide

Save only genuine screenshots captured from your own local DVWA lab. These filenames are suggestions; they are not existing evidence. Do not create mock screenshots or claim a screenshot exists before capturing it.

| Suggested filename | What it should demonstrate |
|---|---|
| `xampp_services_started.png` | XAMPP Control Panel showing Apache and MySQL/MariaDB running. Hide machine-specific or private details if present. |
| `dvwa_setup_status.png` | DVWA setup page showing the setup/database status after you perform initialization. |
| `dvwa_security_level.png` | DVWA Security page showing the level selected for your tests. |
| `tc01_normal_input.png` | The SQL Injection module with the normal input and the actual response visible. |
| `tc02_sql_injection_payload.png` | The SQL Injection module with the demonstration input and actual response visible. |
| `tc03_invalid_input.png` | The SQL Injection module with the invalid input and actual response visible. |

Before sharing a screenshot, inspect it for passwords, browser-saved credentials, session cookies, tokens, personal files, unrelated tabs, or other private data. Crop or redact sensitive information without altering the test result. Do not include database dumps or screenshots containing real user data.
